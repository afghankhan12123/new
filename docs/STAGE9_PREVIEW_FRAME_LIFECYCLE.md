# Preview frame lifecycle after stabilization

The immutable project/render plan owns which source is required at each project timestamp. Primary background supplies cadence independently of layer order. Transition inputs are identified by two stable lane IDs. Required layer intervals and input IDs come from `OverlayCompositorSettings`; a caption/sticker is a later composition pass and cannot authorize a frame without a primary input.

Pause pinning and single-input replay now route through the controller's owned seek path, so they also receive deadline/generation handling instead of issuing an untracked player seek.

A project seek synchronously retires old submitted-output ownership, then the shared playback looper runs graph begin-seek, downstream/compositor/input flushes and end-seek. Input-interval/EOS notifications carry the GL frame generation. The end-seek acknowledgment admits a newer seek only after the queued barrier and only for the matching target/generation. It is not a picture acknowledgment. Readiness comes from real current-generation submitted output; an isolated first-frame event or optimistic player position cannot settle a pending frame deadline. A surface becoming valid after preparation arms the same deadline.

Both compositors exclude adjacent padding from a visible interval. They never synthesize primary video from text, an empty overlay or a global cached frame. Reusable preview period completion is a nonterminal watermark; final sequence EOS remains separate. The shared GL executor and existing downstream-before-upstream teardown/flush ordering remain responsible for borrowed texture leases. Owned output textures, sync fences, effect intermediates and shader programs remain session resources. Preview/export never borrow each other's mutable resources.

A permanent canvas presentation effect delegates Fit/Fill to two preconfigured Media3 Presentation matrices with identical output dimensions. Changing this mode updates the render publication without recreating decoders. A permanent composition background pass fills uncovered pixels using the saved sRGB canvas color converted to linear working RGB. Multi-input compositor output is premultiplied; creative blend equations now handle partially transparent backgrounds before the background pass. The foreground is still applied once. Frame dimensions and primary source orientation/crop retain structural reconfiguration.

Natural playback is protected by a submitted-output progress watchdog in addition to startup/seek deadlines. The last surface image can remain during a bounded landing/recovery; it is not counted as fresh progress. The controller reports Seeking/Recovering and suppresses `isPlaying` before a real initial picture. The UI delays its indicator 350ms to avoid flashing during quick reconfiguration, and suppresses it when an error is visible. Retry appears for recoverable errors only. Diagnostic failures include target and per-input queued PTS/end watermarks. Resource-release errors remain real failures.

The black-primary/caption-only symptom at recording 206s is confirmed visually. Padding rejection prevents one source-proven route to missing underlying content; reduced Fit/Fill rebuilds and stricter readiness improve continuity. A submitted timestamp cannot establish that a decoded source is visually correct or distinguish an intentional black frame. The exact recording failure remains unproven pending the owner's rerun and, if needed, current build logcat/queue diagnostics. No frame-perfect or zero-black-frame runtime guarantee is made.
